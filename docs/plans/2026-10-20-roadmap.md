# LinqToRest roadmap
Status: approved · Date: 2026-10-20

What comes next, in order for the milestones and unordered for the backlog. Each item links where it came from.
Features still go through the `brainstorming` skill and get their own design doc before code.

## Milestone 1 — Catalog sample

A realistic catalog app next to the minimal Shop sample: one API with anonymous browsing and an editor role, a
React front end on the TypeScript client and a Blazor WebAssembly front end on the generated C# client.
Design: [`2026-10-20-catalog-sample-design.md`](2026-10-20-catalog-sample-design.md).

Done when both front ends run the four screens (browse, product page, product editor, categories admin) against
`Catalog.Api`, the sample tests pass, and CI keeps the model, generated clients and the trimmed Blazor publish
current.

## Milestone 2 — Gaps the sample finds (done)

Known before starting; anything new the sample uncovers is added here.

| Item | Why | Constraint risk |
|---|---|---|
| ~~Trim/AOT-safe .NET client~~ | **Done:** [`2026-10-23-aot-client-design.md`](2026-10-23-aot-client-design.md). Blazor WebAssembly Release builds trim; the client reaches generated classes by reflection, so the sample needs a `TrimmerRootAssembly` stopgap. Apps with reflection-based JSON turned off (Native AOT, file-based `dotnet run app.cs`) can't materialize results at all. Generated code could register accessors and a JSON context instead. | Public API (generated code shape, `ClientModel.Bind`); stays BCL-only |
| ~~CORS guidance~~ | **Done:** [`2026-10-24-cors-design.md`](2026-10-24-cors-design.md). Browsers preflight `QUERY`; the README only mentions it. Document the policy (methods, headers, origins) and maybe a helper. | Security: never `*` with credentials |
| ~~Member-level pointers for batch values~~ | **Done**, with server validation rules: [`2026-10-23-field-validation-design.md`](2026-10-23-field-validation-design.md). A rejected value in a batch points at `/operations/N/values`, not the member, so a UI can name the failing entity but not the field (found building the catalog editor). Pointing at `/operations/N/values/<member>` would make field errors possible. | Wire contract (error pointers), both clients |
| ~~Problem → field mapping helpers~~ | **Done** (same design: `RestValidationException.ErrorsFor` / `errorsFor`). Once pointers name members, a small helper per client could map them to form fields. | Public API (both clients) |
